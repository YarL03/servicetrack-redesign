# Сервис Трек · мобильное приложение · v1

Откройте [index.html](index.html) в браузере — это интерактивный каталог экранов. [compare.html](compare.html) показывает три варианта навигации рядом. [notifications.html](notifications.html) показывает шесть экранов уведомлений и переходы между ними. Установка зависимостей и запуск Expo не нужны. Все файлы автономны, внешние шрифты, CDN и API не используются.

Основной пользователь макетов — Иван Иванов, инициалы ИИ. Название приложения — «Сервис Трек». Логотип в `assets/logo.png` — неизменённая копия исходного `assets/logo.png` мобильного проекта, используемого на экране входа по PIN. «Контур» — название источника цветовой палитры, а не бренд приложения.

## Направление, зафиксированное до реализации

Для исполнителя на объекте: быстро найти нужную квартиру, продолжить работу с сохранённого места, отправить результат и решить вопрос с менеджером в контексте заявки.

Источник палитры: `../admin-console-ui/tasks/redesign/v1/theme.css` из корня мобильного проекта. Основные токены взяты без изменения: фон `#F3F5F9`, поверхность `#FFFFFF`, текст `#1C2B43`, вторичный текст `#596980`, акцент `#2858D6`, мягкий акцент `#EBF1FF`. Семантические цвета также из «Контура»: успех `#216B50`, внимание `#86530F`, ошибка `#A72F40`.

Типографика: Segoe UI Variable / системный sans для заголовков, Segoe UI / системный sans для текста; ui-monospace для номеров и показаний. Заголовки 28–30 px, основной текст 16 px, вторичный 14 px, метаданные 12–13 px. Поля и основные действия от 48 px. Отступы 4/8/12/16/24/32, радиусы 12/16/20.

Фирменный приём — синий контур текущей работы: у активной заявки, выбранного шага и основного действия. Он связывает очередь с выполнением. Крупный адрес важнее номера заявки. Для рабочего интерфейса оставлены спокойные поверхности без декоративных иллюстраций и градиентов.

## Три варианта навигации

| Вариант | Структура | Когда полезен | Ограничение |
| --- | --- | --- | --- |
| A · Рабочая очередь — основной | Продолжить → требуют внимания → готовы к работе | Ежедневная работа исполнителя, быстрый возврат к текущей форме | Порядок не является маршрутом и не учитывает SLA |
| B · По адресам | Выбор: улица → заявки либо улица и дом → квартиры | Обход улицы или работы в конкретном доме | Группы должны учитывать город, корпус и строение; без координат не обещать расстояние |
| C · По статусам | Счётчики статусов → вертикальный список | Большой поток, контроль недопусков и доработок | Скрывает распределение по домам; доработка — признак onRevision, а не новый статус |

Рекомендация: A как стартовый экран, B как запоминаемый вид списка. C — альтернативный вид для проверки с исполнителями. Во всех вариантах одинаковы поиск, карточка и четыре постоянных раздела: «Мои», «Все», «Чаты», «Профиль». «Все» сохраняет существующий доступ к общему реестру; реальные полномочия определяются ролью. Центр уведомлений доступен через колокольчик в основных разделах и пункт профиля.

```text
B · По адресам
[Группировка: По улице | По улице и дому]

По улице                      По улице и дому
▾ Лермонтова · 2 заявки        ▾ Лермонтова, 18 · 1 заявка
  Дом 18 · кв. 42                кв. 42 · В работе
  Дом 20 · кв. 47              ▾ Лермонтова, 20 · 1 заявка
▸ Байкальская · 2 заявки         кв. 47 · Готова
```

Переключение применяется сразу. Выбранная группировка сохраняется в localStorage и восстанавливается после перезагрузки. Раскрытые группы и положение списка сохраняются отдельно для каждого режима в текущей вкладке. В примере у улицы Лермонтова есть дома 18 и 20: в одном режиме это одна группа, в другом — две. Группы и счётчики формируются из активных назначенных заявок.

Проверка направления: вместо отдельного «дашборда продуктивности» на первом экране сразу доступна текущая заявка. Вместо карты без гарантированных координат — реальные адресные группы. Сроки, приоритеты и оптимизация маршрута не выдумываются: в текущем IServiceRequest нет подтверждённого времени визита/SLA.

## Основания мобильного UX

- Видимый поиск с подсказкой, областью, недавними запросами и результатами по мере ввода: [Apple HIG — Search fields](https://developer.apple.com/design/human-interface-guidelines/search-fields).
- Постоянные подписанные разделы нижней навигации: [Apple HIG — Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars).
- Области нажатия от 48 px в макете (48 dp в Android, минимум 44 pt в iOS при переносе), достаточный контраст, текстовые названия статусов, доступные альтернативы жестам: [Android — Accessibility](https://developer.android.com/design/ui/mobile/guides/foundations/accessibility).

Это проектные решения, а не результаты пользовательского исследования. Гипотезы нужно проверить на исполнителях с реальными объёмами заявок и условиями связи.

## Исходный процесс

Изучены `src/navigation/routes.tsx`, `src/components/MyServiceRequests/myServiceRequest/MyServiceRequestCard.tsx`, `src/components/ServiceRequests/SearchServiceRequest/SearchServiceRequestModal.tsx`, `src/components/Filters/filters.data.ts`, `src/components/MyServiceRequests/myServiceRequest/inProgress/progress/form/progress-actions.tsx`, `src/components/MyServiceRequests/myServiceRequest/DelayModal.tsx`, типы `serviceRequest.types.ts` / `workContent.types.ts` и уроки offline-синхронизации.

- Сейчас: отдельные «Мои» и «Все», поиск по числовому ID; параметры адреса доступны в фильтрах. Предложено: одна строка для номера, внешнего номера, адреса и абонента с явно выбранной областью. Поиск по всему серверному реестру требует соответствующего API; локальный прототип ищет только по демонстрационным данным.
- Сейчас: для новой работы — подробная карточка с действием внизу → постраничная форма; для IN_PROGRESS уже существует прямой переход в форму через MyServiceRequestItem. Кнопка формы меняется между «Сохранить», «Далее», «Завершить». Предложено: сделать продолжение визуально явным, сократить карточку перед стартом, показать названия этапов, закрепить действие и добавить проверку перед отправкой. Прямой вход в текущую работу — сохранение существующей возможности, не новая функция.
- Уже существующие черновики, предварительное сохранение и offline-очередь сохраняют свои обязательные условия. Локальное сохранение не называется отправкой, ожидание подтверждения не называется выполнением.
- Недопуск сохраняет обязательное фото уведомления, необязательный акт, дату/время и комментарий до 400 символов.

## Состав и границы

24 экрана и пояснения перечислены в `data.js` и `notifications.data.js`; разметка экранов — `screens.js`, общие компоненты — `components.js`, поведение — `app.js`; уведомления выделены в `notifications.js` / `notifications.css`; токены и адаптация — `styles.css`. [UX-спецификация](UX.md) описывает исполнение, чат, требования к данным и ограничения. [Галерея из 60 PNG](previews/index.html) включает все экраны и дополнительные состояния. [Отчёт браузерной проверки](qa/report.json): 100 проверок компоновки на четырёх ширинах и 82 сценария, без ошибок JavaScript.

Данные вымышлены. Макет не подключается к серверу и не изменяет исходное приложение. Ввод полей демонстрационной формы сохраняется в localStorage отдельно по ID заявки. Настройка адресной группировки также сохраняется локально. Сообщения, уведомления, разрешения push, настройки доставки, выбранные файлы, статусы, фильтры и выбор вида живут в текущей вкладке до перезагрузки; полноценное offline-хранилище не реализовано. Кнопка «Сбросить демонстрацию» очищает локальные черновики и настройку группировки макета. Демонстрационные фото обозначены как примеры, нативная камера и запись аудио не реализованы. Выбранные реальные файлы остаются в памяти браузера и не уходят в сеть.

Чаты, полнотекстовый поиск, сводный экран проверки и новая структура навигации — предложения для реализации. Лимиты чата 25 МБ/файл и 5 файлов/сообщение — параметры концепции, не ограничения существующего API. Настоящая доставка, просмотр Office/PDF, push, разбор конфликтов и доступ по ролям требуют реализации и интеграционного тестирования.

## Проверить самостоятельно

1. Открыть `index.html`; в каталоге выбрать A, B и C либо открыть `compare.html`. В варианте B переключить «По улице» / «По улице и дому», открыть заявку и вернуться. Прямые ссылки: [по улице](index.html?grouping=street#locations), [по улице и дому](index.html?grouping=street-house#locations). Параметр `grouping` задаёт стартовый вариант демонстрации; без него восстанавливается сохранённый выбор.
2. В поиске ввести «Лермонтова», «10428», «ИРК-8241», «Смирнова» или заведомо отсутствующий запрос. Переключить область и применить фильтры.
3. В текущей работе ввести `12,5`, добавить пример фото, открыть проверку и завершить. Включить «Без сети» в панели пояснений до завершения для сценария очереди отправки.
4. Открыть чат, написать текст, добавить пример PDF или локальный файл; проверить роль менеджера, ошибку отправки и повтор.
5. Открыть колокольчик: выбрать непрочитанные и категорию, открыть событие и нужную заявку/сообщение; вернуться к той же подборке. В меню проверить отметки и удаление с отменой.
6. В каталоге выбрать «Событие во время работы»: заполнить поле, перейти в чат и вернуться. В панели пояснений доступны имитация входящего push, загрузки, ошибки, пустой ленты и работы без сети.
7. Открыть настройки уведомлений: разрешить/запретить push, проверить тихие часы и приватность предпросмотра. Полные правила и отличия от текущего API — [NOTIFICATIONS.md](NOTIFICATIONS.md).
8. Открыть недопуск: без фото уведомления сохранение не проходит, после фото — доступно.

Браузерная проверка без зависимостей:

```bash
node tasks/redesign/v1/qa/browser.cjs
```

Нужен Chromium; альтернативный путь задаётся переменной `REDESIGN_BROWSER`. Проверяются компоновка, поиск, фильтры, формы, локальные черновики, offline-исход, чат, вложения, история переходов и диалог с клавиатурой. Проверка нативных экранов, VoiceOver/TalkBack и системной клавиатуры на устройстве остаётся задачей реализации.
