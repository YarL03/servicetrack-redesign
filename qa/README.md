# Проверка макетов

Проверка выполняется локальным Chromium через Chrome DevTools Protocol, без npm-зависимостей, сети и рабочего API. Канал управления — pipe. Полный результат находится в [browser-report.json](browser-report.json).

Итог 03.11.2026: **успешно в обеих темах**. Для каждой темы выполнены 5 964 проверки экранов, 426 проверок диалогов и 52 проверки взаимодействий. В тёмной теме дополнительно выполнено 6 390 проверок фона и текста панелей/полей. Ошибок JavaScript, битых переходов и выходящих за границы элементов не обнаружено. Сохранено 122 PNG-превью: по 61 на тему.

Светлая тема: [browser-report.json](browser-report.json). Тёмная: [dark-browser-report.json](dark-browser-report.json). Проверка цветов обнаруживает оставшиеся светлые поверхности или тёмный текст; это не полный аудит WCAG.

Дополнительный итоговый прогон [dark-quick-report.json](dark-quick-report.json) прошёл 48 проверок экранов и 55 взаимодействий, включая реальный DOM встроенного превью через CDP: тема меняется в обе стороны, поле и узел DOM сохраняются; управление каталогом помещается на 320 px.

Покрытие:

- Все 142 экрана × три варианта × 14 ширин: 320, 390, 599, 600, 768, 899, 900, 1024, 1199, 1200, 1440, 1535, 1536, 1920 px.
- Проверка фактически отрисованного ID экрана, наличия заголовка и содержимого, отсутствия горизонтального переполнения документа и выхода элементов управления за экран.
- Проверка существования всех внутренних переходов `#ID`, `go:ID`, `modal:ID`; сбор ошибок JavaScript.
- Все диалоги дополнительно открываются поверх страницы на 320 и 1440 px во всех вариантах. Проверяются границы полей и кнопок внутри диалога.
- Мобильное меню, переход из меню, фокус в диалоге, закрытие Escape, обязательные поля формы, переход к основному содержимому с клавиатуры, добавление этапа и группы в конструкторе.
- Каталог: выбор варианта/экрана/брейкпоинта, поиск и тема. Проверяется сохранение полей/DOM и открытых диалогов, localStorage, приоритет прямой ссылки, передача темы в превью и ссылку полного размера.
- PNG: четыре ключевых экрана (дашборд, список заявок, рабочая форма, конструктор) × пять контрольных ширин × три варианта × две темы; отдельное превью каталога для каждой темы.

Сценарии массового обхода вызывают тот же `RD.render(id)`, что использует маршрутизатор. Это избегает ограничения Chrome на тысячи изменений History API подряд. Обычная навигация по ссылкам проверяется отдельными взаимодействиями. Скриншоты снимаются после завершения рендера и композиции кадра. На снимках показана видимая область окна; остальные блоки доступны прокруткой в HTML.

Команды из корня проекта:

```bash
node tasks/redesign/qa/browser-check.cjs --full --theme=light --screenshots
node tasks/redesign/qa/browser-check.cjs --full --theme=dark --screenshots
```

Для другого установленного Chromium:

```bash
REDESIGN_BROWSER=/path/to/chrome node tasks/redesign/qa/browser-check.cjs --full
```

Все JavaScript-файлы проходят `node --check`; все 142 рендера отдельно выполняются в Node VM. Девять CSS-файлов разбираются PostCSS из существующих зависимостей фронтенда. Визуально просмотрены desktop/mobile макеты, планшетная форма и каталог.

Граница проверки: это локальные HTML-макеты. Production-сборка и API-интеграция не менялись и в этот результат не входят. Полная проверка Safari/Firefox и настоящих медиа, карт, оплат и серверной валидации не выполнялась.
